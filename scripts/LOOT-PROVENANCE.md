Generated by `scripts/Build-Loot.py`. **Source of boss->item associations:** wowtbc.gg Warcraft Forever loot tables (Forever-specific; flags Forever-new items). **Item IDs** are verified against Forever's own client `Item` table (names from Forever `ItemSparse`, falling back to Classic Era `ItemSparse` when Forever's export omits the name). Forever-*new* items have no name in the client tables, so their IDs come from foreverdb.net item links (`generated/loot/foreverdb-ids.json`) and are shipped only when that ID exists in Forever's `Item` table and its equip slot fits the listing. Quality is *not* used to match Classic-named items because Forever revised dungeon item quality (e.g. Cursed Felblade is green in Classic, blue in Forever); in-game tooltips are the authority for stats.

**Not shipped, on purpose:** (1) drop percentages: the Forever listing's numbers are not stated as Forever-measured and `foreverdb.net` says its values are Classic data with "no drops seen in Forever yet"; (2) Forever-*new* items whose numeric ID could not be verified (not linked by foreverdb.net, or the linked ID is not in Forever's Item table / does not fit the slot); (3) name collisions between a Classic ID and a Forever-reissued ID (e.g. Robe of Doan 7711 vs 217297) where the evidence does not decide.

Confidence: **forever-corroborated** = boss->item names agree across two Forever listings and the IDs across two ID-bearing databases; **forever-listed** = one Forever listing, ID verified in client tables (Forever-new items: foreverdb.net ID checked against the Item table). `Forever-specific` = the listing is a Forever database (true for all shipped rows); it does not claim the drop was observed in Forever.
